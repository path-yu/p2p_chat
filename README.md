# Lumen · 点对点聊天

用 Go + [MyGo](https://github.com/egoist/mygo) 原生 UI 写的去中心化聊天应用：没有服务器、没有账号、没有云端。
每个节点自带一对 Ed25519 身份密钥，和遇见的节点做 X25519 握手后用 AES-256-GCM 传输，写下的每条消息都签名，
再由相邻节点继续转发——任意两个节点不必直连，也能把话带到。

界面是 MyGo 的 `ui` 包直接画在 GPU 上的原生窗口（Windows 用 Direct3D 11），不是 WebView，也不是网页套壳。
窗口自绘标题栏，右上角保留系统原生的最小化 / 最大化 / 关闭三个按钮，图标、配色都跟着日间 / 深色一起变。

## 跑起来

```bash
.\tools\build.ps1             # 编出 lumen.exe（窗口）和 lumend.exe（终端）
go run .                      # 直接跑也行，但 go run 自己会带一个控制台窗口
go run . -appearance dark     # 强制深色（auto / light / dark）
.\lumend.exe -network mynet   # 终端里的节点：一行字一行字地发
```

**为什么双击 `lumen.exe` 不该弹黑框**：Go 默认把 Windows 程序编成**控制台子系统**（PE subsystem = 3），
双击时系统就先给你一个 cmd 窗口。窗口版要用 `-H=windowsgui` 改成 GUI 子系统（subsystem = 2）：

```bash
go build -ldflags "-H=windowsgui -s -w" -o lumen.exe .   # 窗口版，无控制台
go build -ldflags "-s -w" -o lumend.exe ./cmd/lumend     # 终端/服务器版，保留控制台
```

`tools/build.ps1` 就是这么编的（加 `-Linux` 顺带交叉编译服务器版），两个产物分工：

| 文件 | 子系统 | 用途 |
| --- | --- | --- |
| `lumen.exe` | GUI | 双击只有窗口；启动出错写进 `~/.lumen/lumen.log` |
| `lumend.exe` | 控制台 | 两个终端互测、云主机上的服务器节点、SSH 里打字聊天 |

### 让两台机器聊上

**同一局域网**：都打开 Lumen，2～3 秒内互相发现（UDP 广播，默认端口 47822），侧栏「在线设备」会出现对方。

**两台在不同网络**：什么都不用配，打开就会自己找——这是这一版的重点，见下面「跨网穿透」。

**第一次运行会弹 Windows 防火墙授权**：必须点「允许访问」（专用网络和公用网络都勾上），
否则入站的 UDP 全被挡掉，界面会显示"可打洞"却始终连不上。

窗口中间那两行地址是**同时给的**，各管一段路：

| 行 | 例子 | 用途 |
| --- | --- | --- |
| 公网 | `111.179.37.222:47823` | 跨网用，UDP 打洞端口，由 STUN 问出来 |
| 内网 | `192.168.110.188:47821` | 同一个 Wi-Fi 用，TCP 监听端口，直连最快 |

公网那行在启动后 1~3 秒内是「获取中…」（STUN 还没回来），UDP 出不去时写「不可用」；
点哪一行就复制哪一行。

**手动兜底**：把窗口里的邀请地址发给对方，他在欢迎页的「手动连接」里粘上、回车
（`Ctrl/⌘ + L` 同样打开这个输入框；地址是监听端口就直连，是打洞端口就打洞，两种都会试）。

但**打洞要两边同时往外发**：家用路由器多是"端口限制锥"，只放行你主动发过包的地址，
对方单方面打进来的第一个包会被 NAT 丢掉。所以：

| 你这边显示 | 对方要做的 |
| --- | --- |
| 可直连（路由器已放行端口） | 粘一次你的地址就行 |
| 可打洞 / 打洞受限 | **双方各粘一次对方的地址**，然后各自回车 |

最省事的还是同一个 `-network`：两边都会在 DHT 里宣告，谁也不用粘。

命令行同样可以：

```bash
./lumen.exe -peer 192.168.1.7:47821          # TCP 直连（对方端口可达时）
./lumen.exe -punch 1.2.3.4:47823             # UDP 打洞（双方都能出 UDP 时）
```

命令行参数：`-port` 监听端口、`-udp-port` 打洞端口、`-discovery-port` 发现端口、
`-network` 会合网络名、`-lookup` / `-announce` 查找与宣告间隔、`-no-dht` 关闭会合、
`-stun` 自选 STUN 服务器、
`-dir` 数据目录、`-name` 显示名、`-appearance` 外观。

### 窗口外观

- 标题栏是应用自己画的：左边是图标与名字，右边是日间 / 深色切换，再往右留给系统的三个窗口按钮。
- 三个按钮是系统原生控件（可拖动、双击标题栏最大化、贴边分屏都照旧），MyGo 的 `SetWindowButtonsTheme`
  让它们的描边跟着应用深浅色走。
- 点标题栏的太阳 / 月亮即切换，选择写进 `settings.json`，下次启动照旧；`-appearance auto|light|dark`
  可以在命令行上强制一次。
- 应用图标由 `icon.go` 用距离场画成 PNG（蓝色圆角方块 + 交叉轨道），启动时 `Window.SetIcon` 交给系统，
  任务栏与窗口图标都用它；`go test -run TestAppIcon .` 会把它写到 `testdata/icon.png`。

### 快捷键

| 键 | 作用 |
| --- | --- |
| `Enter` | 发送 |
| `Ctrl/⌘ + I` | 打开 / 关闭「节点信息」 |
| `Ctrl/⌘ + K` | 复制自己的邀请地址 |
| `Ctrl/⌘ + L` | 打开 / 关闭「手动连接」输入框 |
| `Ctrl/⌘ + P` | 打开「个人资料」对话框 |

**个人资料**：点侧栏左下角自己那一行（或 `Ctrl/⌘ + P`）弹出对话框，一次改两样——
昵称，以及头像的**颜色**（6 组渐变）和**图标**（首字 / 轨道 / # / 月亮 / 太阳 / 地球 / 盾牌 / 人群）。
预览就在对话框左上角，选完点保存。资料写进 `identity.json`（重启还在），并通过 `hello`
广播给已连接的节点，对方的侧栏和之后的消息气泡会立刻跟着变。

## 跨网穿透

两个在不同网络里的节点，要"打开就能找到对方"，得同时解决三件事：知道自己在公网上是谁、
让包能进得来、在没有服务器的情况下互相找到。Lumen 用三样公开的基础设施做到，一行配置都不用：

1. **STUN（RFC 5389）** — `internal/nat/stun.go`
   用打洞那个 UDP 套接字去问 STUN 服务器："你看到我是谁？"
   两个答案端口一致 → 锥形 NAT（别人的包打得进来），不一致 → 对称 NAT（只能靠中继）。
   拿到的是**这个套接字的公网 IP:端口**，也就是对面该往哪儿打、也是宣告给会合网络的地址。

   默认服务器按实测延迟排：芒果TV `stun.hitv.com:3478`、斗鱼 `stun.douyucdn.cn:18000`、
   哔哩哔哩 `stun.chat.bilibili.com:3478`、小米 `stun.miwifi.com:3478`（国内 50~70 ms），
   再用 Google / Cloudflare 兜底。换掉它们：`-stun host:port,host:port`；
   想知道哪个快：`go run ./cmd/stunprobe`（并发探测一批，打印延迟与它看到的地址）。
   STUN 服务器只会看到你的公网 IP，收不到名字、消息或任何身份信息。

2. **UDP 打洞** — `internal/p2p/punch.go` + `internal/p2p/udp.go`
   两边同时向对方的公网端点发包，各自的 NAT 因此留下一条出向映射，回包就能进来。
   任一侧先动手，另一侧在收到陌生打洞包时会**回打**，所以单向发起也能成。
   打通之后这条 UDP 路径交给一个自己实现的**可靠流**（序号、累计确认、超时重传、窗口，见 `udp.go`），
   它实现了 `net.Conn`，于是握手、AES-GCM 帧、签名、中继**原封不动**地跑在上面。

3. **DHT 会合（BitTorrent 主线 DHT，BEP 5）** — `internal/dht/`
   没有服务器也能约在一个地方见：双方把网络名哈希成 20 字节，作为 infohash 加入同一个 swarm，
   向离这个键最近的节点 `announce_peer` 自己的公网端口，再 `get_peers` 看别人宣告了什么。
   查到的候选端点直接丢给打洞。DHT 只是邮局，不转发消息，消息始终点对点。

4. **UPnP-IGD（可选加分）** — `internal/nat/upnp.go`
   路由器支持 UPnP 时顺手要一个 TCP/UDP 端口映射，这样即使不打洞也能被直接连上；
   没有 UPnP 也不影响打洞。

界面直接把结论摆出来，不用自己推断：

- 侧栏左下角一行：`可直连` / `可打洞` / `打洞受限` / `打洞不可用` / `仅局域网`
- 欢迎页状态：`等待节点… · 可打洞`
- 「节点信息 → 跨网穿透」卡片第一行：**能否打洞** + 圆点 + 结论，后面才是
  你的网络（锥形 / 对称 NAT）、公网地址、端口映射、会合网络、DHT 表大小与发现数，
  最后一句用大白话解释这个结论意味着什么。

**已知边界**：对称型 NAT / CGNAT 且路由器不支持 UPnP 时，打洞无法成功，需要中继（下一版）；
DHT 用公共基础设施，首次宣告通常要 20～40 秒；`-network` 相同才会互相发现（默认 `lumen`，
想只和自己人连就换一个名字）。

## 在一台电脑上怎么试

只有一台机器，能验证的比想象中多：**打洞、可靠 UDP、加密握手、消息投递**全都能在本机跑通，
唯一跑不了的是"两个不同的公网出口"，那需要第二个网络。

### 1. 一条命令，两个终端

```
.\tools\demo.ps1          # 开两个终端窗口，一边打字另一边立刻收到
.\tools\demo.ps1 -Gui     # 左边开窗口，右边开终端，能看着气泡冒出来
.\tools\demo.ps1 -DryRun  # 只打印要跑的命令，不启动
```

它做的事：甲在 TCP 47821 / UDP 47823 上起一个节点，乙在 47831 / 47833 上起另一个，
乙用 `-punch 127.0.0.1:47823` 朝甲打洞，甲收到陌生打洞包会自动回打，于是双向打通。
在任一终端里打一行字回车，另一边会打出 `[大厅] 某某: …`；开窗口时侧栏的对方地址会标着「打洞」。

### 2. 自动化的那一份

```bash
go test ./internal/p2p -run TestPunch -v   # 打洞 → 可靠流 → 握手 → 签名消息，一步不落
go test ./...                              # STUN 报文、bencode、DHT 会合、打洞、图标
```

### 3. 看公网那一半（单机也能看）

直接开窗口（或 `demo.ps1 -WithDHT`），等 20～40 秒，右侧「节点信息 → 跨网穿透」会填上：
公网地址、NAT 类型、DHT 表里的节点数、发现数。两个同 `-network` 的实例会互相在 DHT 里找到对方的公网端点——
但它们共用同一个出口 IP，打洞会变成 hairpin，家庭路由器大多不放行，**这一步单机注定连不上，不是 bug**。

### 4. 真正的跨网验证（一台电脑也做得到）

需要的是「第二个公网出口」，不是第二台电脑：

- **云主机**（最省事，任意 1 核 Linux）：
  ```bash
  GOOS=linux GOARCH=amd64 go build -o lumen-linux .
  scp lumen-linux root@你的云主机:/root/
  ssh root@你的云主机 'chmod +x lumen-linux && ./lumen-linux -port 47821 -udp-port 47823 -network mytest'
  ```
  本机跑 `lumen.exe -network mytest`，两边会各自报出公网地址，几十秒后自动连上，
  终端里出现 `＋ 某某 连上了`。
- **手机热点**：把其中一台设备切到热点，另一台留在原网络，效果同上。

### 判读

| 看到什么 | 说明 |
| --- | --- |
| 侧栏「在线设备」出现地址，不带标记 | 局域网直连（TCP） |
| 地址前带「打洞 ·」 | 走的是 UDP 打洞链路 |
| 卡在「发现 0」 | DHT 还没收敛，再等 30 秒；或网络封了 UDP |
| 跨网穿透卡片写「未打通」 | STUN 没通（网络封 UDP），只剩局域网与手动地址 |
| NAT 显示「对称，需中继」 | 打洞大概率失败，需要下一版的中继 |

日志都在各自的数据目录里：`lumen.log`（穿透每一步）、`history.jsonl`（消息）。

## 部署到 Linux 服务器（最可靠的跨网验证）

服务器有公网 IP、没有 NAT，所以"笔记本 ↔ 服务器"这条链路连打洞都不用赌运气：
即使你在对称 NAT 后面，出向的包也能到达服务器，服务器回的包正好落在你刚建立的映射上。

服务器侧是一个**不含图形库**的单文件守护进程 `cmd/lumend`（纯 Go、静态、6 MB 左右），
`lumen` 是窗口版，`lumend` 是无窗口版，两者说同一套协议。

```bash
bash tools/deploy.sh root@1.2.3.4          # 编译 + scp + 装到 /usr/local/bin/lumend
bash tools/deploy.sh root@1.2.3.4 50000    # 换端口（TCP 50000 / UDP 50002）
ARCH=arm64 bash tools/deploy.sh root@1.2.3.4
```

然后在服务器上：

```bash
lumend -network mynet -port 47821 -udp-port 47823
# 或者挂着跑：
nohup lumend -network mynet -port 47821 -udp-port 47823 > ~/lumen.out 2>&1 &
tail -f ~/lumen.out
```

**别忘了云控制台的「安全组 / 防火墙」放行 `UDP 47823`**（打洞要它），
`TCP 47821` 可选（放行后能直连，更快）。

本机用同一个网络名就自动找到它：

```powershell
.\lumen.exe -network mynet
```

服务器终端里打的字会出现在你的窗口里，你发的消息也会出现在服务器的终端里。
服务器端日志写在 `~/.lumen/lumen.log`，重启后历史还在 `history.jsonl`。

想做成开机自启（systemd）：

```ini
# /etc/systemd/system/lumend.service
[Unit]
Description=Lumen node
After=network-online.target

[Service]
ExecStart=/usr/local/bin/lumend -network mynet -port 47821 -udp-port 47823 -name 机房
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now lumend && journalctl -u lumend -f
```

## 私聊

点侧栏「在线设备」里的任何一台，就开一个只属于你和他的会话：

- 侧栏多出「私聊」一节，频道和私聊分开列
- 标题栏写 `私聊 · 只有对方收得到`（对方掉线时变成 `对方不在线`）
- 输入框提示变成 `发消息给 某某`

**为什么"只有对方收得到"**：消息带收件人字段（`to`），发的时候**只走那条直连**，
不进入中继队列；其他节点即使收到也会立刻丢弃。所以私聊不会经过第三方，
代价是**只在直连时可用**——中间隔了一层节点就发不出去（这时标题会写"对方不在线"）。

私聊历史按房间存在 `history.jsonl` 里，下次启动会一起带回来。

## 没有人在线时

发出去的消息不会凭空消失，也不会假装送到：

- 气泡下面标 `待发送 · 14:03`；
- 标题栏写 `3 条待发送 · 有人连上就补发`；
- 队列最多留 50 条，最早的先丢；
- 第一个节点连上的瞬间按原顺序补发，**消息 ID 不变**，所以对方即使已经收到过，
  也只会按重复丢弃，不会出现两条一样的。

## 打洞与稳定性

打洞的成功率和"接上以后会不会掉"是两件事，分开治。

**提高打洞成功率**

| 做法 | 为什么 |
| --- | --- |
| 起始先打一串密集包（12 个，30 ms 间隔） | 两边必须在对方映射存在的时间窗里同时发包；密集的起始窗口比 200 ms 一个更容易撞上 |
| 一次打多个候选端点（最多 3 个） | 一次 lookup 常拿到多个地址，先响的那个才是该留的；上限防止陈旧表变成洪水 |
| 打洞超时**立刻**重新查表 | 超时通常意味着对方地址变了，等 45 秒下一轮太慢（限流 10 秒一次） |
| 邻近端口预测 | NAT 改写源端口时常按顺序分配，公布的门可能就在旁边。3 秒无回应后，对**同一台主机**再试 +1/+2/+3/−1/+4 五个端口，绝不换 IP；命中会记一行日志 |

**接上以后不掉**

- **保活**：每 15 秒给每个打洞对端发 5 字节。NAT 的映射是**按对端**记的，
  对 STUN 服务器的心跳保不住跟对端的那扇门——这是之前"每 40 秒断一次"的根因。
- **快速重连**：断开后按 1/3/8/20/45 秒重打（原来 2/8/20/40），且优先用原地址。
- **拥塞窗口**：空闲期不发包，链路不会被误判为满载。

实测：两个节点空闲 **95 秒，0 次断开**（改造前 40 秒必断）。

## 传文件

三种方式发起：回形针选文件（**可多选**）、文件夹按钮整目录、或者**把文件拖进输入框**。
`lumend -send 路径` 也行。

拖进来（或选完文件）不会立刻发送，而是变成输入框上方的**附件条**：

```
[📄 季度报告.pdf ×] [📄 2024 ×] [📄 setup.exe ×]
[📎] [📁] [ 发消息到 #大厅            ➤ ]
```

拖动经过输入框时边框变蓝、占位文字变成「松手添加附件」；回车连同文字一起发出去。
没有连上节点时附件**留在输入框里**，不会丢。

对方会收到一张卡片：

```
┌──────────────────────────────┐
│ 📄 send8mb.bin                │
│ 8.0 MB / 8.0 MB · 51%         │
│ ████████████░░░░░░            │
│ [接收] [拒绝]                  │
└──────────────────────────────┘
```

- **卡片上显示实时速度**：`583.1 MB / 1.0 GB · 92.6 MB/s · 50%`，速度是 0.7/0.3 的指数平滑，
  不会跳来跳去；
- **右键卡片**：在资源管理器中打开（定位到文件，窗口会**强制前置**，不会被应用盖住）、复制文件路径；
- **必须先接受**，没有自动收：卡片上按钮点下去才开始传；
- 传完自动 SHA-256 校验，对得上才改名落盘，对不上留在 `.part` 并报错；
- **保存目录可改**：「节点信息 → 文件 → 更改目录」，选完记在 `settings.json`，重启还在；
  默认 `~/Downloads/Lumen/`；
- **整目录**：发文件夹时按 `filepath.Walk` 展开，相对路径随清单一起过去，对方还原同样的目录结构；
- **文件名会先"洗"一遍**：Windows 不接受的 `: * ? " < > |` 换成 `_`，结尾的点和空格去掉，
  `..` 和绝对路径被掐掉——别的系统传过来的名字不会让写入失败，也不会跳出下载目录；
- **长路径**：目标路径超过 240 字符时自动加 `\\?\` 前缀，深层嵌套的目录也能落盘；
- **断点续传按块补**：每个文件切成 32 KiB 的块，接收端把"哪些块已经有了"记在位图里
  （随 `.part` 存成 `.part.lumen` 边车）。重连后它把位图发给发送端，发送端**只补缺的块**，
  不要求连续——中间的洞也能补。实测断在 53% 时，重连从 550 MB 接着传；
  位图里记着文件的**标签**：同名但内容不同的文件不会被误当成续传（否则会跳过块、文件被写坏）；
- 传大文件时聊天不会卡：每块 32 KiB，一条消息最多排在一块的后面（5 MB/s 时约 6 毫秒）。

命令行对测：

```bash
./lumend.exe -recv ./下载目录          # 收到就自动接收
./lumend.exe -send ./big.iso -punch 1.2.3.4:47823
```

实测（本机回环，所以是上限不是典型值）：

| 文件 | 用时 | 速度 | 校验 |
| --- | --- | --- | --- |
| 8 MiB | < 1 s | — | MD5 两端一致 |
| 文件夹（4 文件 / 35 MB / 三层子目录） | 约 1 秒 | 165 MB/s | 4 个文件 MD5 全一致，结构一致 |
| 1 GB | **约 9 秒** | 起 45 MB/s，峰值 173 MB/s，平均约 **114 MB/s** | MD5 两端一致 |
| 1 GB（断在 53% 后续传） | 6 秒补齐 | 从 550 MB 接着传 | MD5 两端一致 |
| 文件夹（4 个文件 / 35 MB，含三层子目录） | 约 1 秒 | 165 MB/s | 4 个文件 MD5 全一致，目录结构一致 |

跨网会低得多：50 ms RTT 的链路受拥塞窗口限制约 5 MB/s，1 GB 大概 3~4 分钟。

## 拥塞控制

打洞链路跑在自研的可靠流上，窗口不再固定，而是像 TCP 一样自适应（`internal/p2p/congestion.go`）：

| 机制 | 做法 |
| --- | --- |
| 起步 | 16 个包，之后指数增长（慢启动）到阈值 |
| 增长 | 阈值之上每 RTT 加一个包（拥塞避免） |
| 丢包 | 三个重复 ACK 立即重传，窗口减半（快速恢复） |
| 超时 | 窗口降为 1 个包，重新慢启动 |
| RTT | Jacobson/Karels 平滑，RTO 在 200 ms ~ 3 s 之间自适应 |
| 断线判定 | 最老的那个包重发 `-retries` 次（默认 20，约 6 秒）仍无 ACK 才断开 |

`-retries` 可调：链路抖动大的环境调大（更耐心），想快速发现掉线调小。

## 协议

自己实现的一层小协议（`internal/wire`），不依赖 libp2p：

```
TCP 连接
  ├─ 握手（明文，1 行 JSON）
  │    hello{v, id, pk, e, s, name, addr}
  │    · e 是本次连接的 X25519 临时公钥
  │    · s 是身份私钥对 "lumen/hs/v1|e" 的签名 → 会话与身份绑定，防中间人
  │    · 双方同时发 hello，读完对方的后校验：签名、pk 与 id 的哈希是否一致
  ├─ 会话密钥 = HKDF-SHA256(X25519 共享密钥, salt=排序后的两个 peer id)
  └─ 之后每一帧 = uint32 长度 + 12 字节随机 nonce + AES-256-GCM 密文
```

信封（`Envelope`）字段：`t` 类型、`id` 消息 ID、`from` 发送者、`room` 频道、`body` 正文、`ts`、`ttl`、`sig`、`pk`。
`chat` / `typing` 用长期身份私钥签名，签名覆盖 `t|id|from|room|ts|body`。
中继节点只改 `ttl`、不做解密，因此**转发者无法篡改或冒充**，收到方一律验签并核对 `from == hash(pk)`。

| 消息 | 用途 |
| --- | --- |
| `hello` | 连上后互报名字与已知地址 |
| `chat` | 频道消息，`ttl` 从 4 递减，逐跳中继 |
| `typing` | 「正在输入…」（1.2 秒节流） |
| `peers` | 交换已知地址，让网状网自己闭合 |
| `ping` / `pong` | 每 5 秒测一次往返时延 |

去重靠消息 ID 的 seen 表；同时互连的去重靠「保留小 ID 一方主动发起的那条连接」。
局域网发现：每 3 秒向各网卡的广播地址发 UDP beacon，收到就按 `addr` 回连（端口被占用时自动降级为手动地址）。

## 数据

`~/.lumen/`（或 `-dir` 指定）下：

- `identity.json` — 身份密钥，权限 0600，**别删**，删了就是另一个人
- `settings.json` — 显示名与上次的频道
- `history.jsonl` — 逐行追加的消息历史，启动时读最近 400 条

## 已知边界

- 面向局域网：公网互连需要自己做端口映射（TCP 47821），发现走广播，不支持穿透 NAT。
- 消息是「尽力而为」的洪泛中继，没有补发与离线队列；离线期间的消息不会补投。
- 没有历史同步：每个节点只存自己看到过的消息。
- 房间是标签而不是订阅：节点会收到所有房间的消息，界面按房间过滤（省一次订阅协议，代价是带宽）。
